# 設計方針 — 何を独自要素にするか

このアプリが他の英単語アプリと何が違うのか、なぜその作りなのか、そして
**何を作らないと決めたのか**を書いた文書。実装順もここにある。

README が「いま何ができるか」を書くのに対して、これは「なぜそうするか」と
「次に何をするか」を書く。判断を変えるときは、ここの根拠ごと書き換えること。

---

## 看板の一文

> **読めない理由を、語彙・構文・速度に切り分ける。そして知らない語は、分解して当てる。**

競合の一文と並べると位置が分かる。

| | 一文 |
| --- | --- |
| mikan | 速く、たくさん（利用者700万人超・市販単語帳140冊以上を収録） |
| abceed | AIが最適化、市販教材が全部入り、自動採点 |
| Monoxer | AIが記憶度を推定して問題を自動生成（導入2,500教室超） |
| Anki | 何でも自分で作れる |
| **Eitangoze** | **読めない理由を診断する。根拠は全部データで出せる** |

## 診断 — なぜこのままだと埋もれるのか

独自要素が**無い**のではない。SemCor の語義比率、同語根ファミリー、消えていく英文、
98%まであとN語、試験日逆算、語義単位のスケジューリング、8種のカード。どれも競合には無い。

問題は**この7つを一文で言えなかったこと**と、**看板にすべき機能が奥に埋まっていたこと**、
そして**看板候補の実測品質が悪かったこと**の3つ。

以下、実測した数字を根拠に順に潰す。

---

## 実測した3つの事実

### 1. 語義比率が 42% 壊れている

同梱DBを直接集計した結果:

```
2語義以上に SemCor 頻度がある単語        3,743
  うち1位と2位の日本語訳が重複している    1,572  (42%)
  訳が別物                               2,171
```

WordNet の細かすぎる語義が、同じ日本語訳に潰れている。

```
make   1位:為す    → 2位(32%):為す
come   1位:到来    → 2位(31%):到来
time   1位:時      → 2位(27%):時
become 1位:なる    → 2位(40%):なる
```

そして `data/Cards.kt` の文脈判別カードは、誤答選択肢を「同じ語の別の語義」から作り、
`it != correct` の完全一致でしか弾いていない。つまり
**「この文の think はどの意味？ ①考える ②考える、思う」という答えられない問題が出る。**

看板に据える前に掃除が要る。→ 実装順 ①

### 2. 同語根ファミリーは 2.8% しかカバーしていない

```
見出し総数            18,575
root 文字列を持つ語     5,145   ← 語根は判明している
ファミリーに入れた語       528   ← 仲間が見つかったのはこれだけ (2.8%)
語根ファミリー数           71
```

**4,617語が孤児。** 語根は分かっているのに同じ根を持つ仲間が居ないので何も表示されない。

原因は `tools/step2_wiktionary.py` の1行:

```python
if lang in SOURCE_LANGS and form and not form.startswith("-") \
        and not form.endswith("-") and len(form) >= 3:
```

`-` で始まる／終わる形（＝接頭辞と接尾辞）をここで捨てている。接辞データは
**すでに kaikki の `etymology_templates` の中にあって、読み飛ばしているだけ**。
新しい取得元は要らない。→ 実装順 ④

### 3. 「いま何%読めるか」は情報としての価値がゼロ

読めば分かる。読者本人が正解データなのに、予測モデルの数字を出すのは情報としてマイナス。

読んでも分からないことは3つしかない。

| | 読めば分かる？ | 扱い |
| --- | --- | --- |
| 知らない語がどれか | 分かる | 可視化する価値なし |
| いま何%読めるか | 分かる | **看板から降ろす**。内訳の一行に格下げ |
| 3か月後に読めるか | 分からない | `ui/screens/FadingText.kt` が既に答えている。据え置き |
| 98%まであと何語・どの順 | 分からない | 情報としては正しいが、体験ではなく数字 |
| **知っているつもりで取り違えている語** | **分からない** | **ここが空白。看板にする** |

最後の行が本命である理由:

> **知らない語は辞書を引く。知っているつもりの語は引かない。**

`abstract` を「抽象的な」で読み飛ばした人は、読んでも自分が間違えたことに気づかない。
誤読は自己申告されない。だから読者本人は正解データになれず、外から教えるしかない。

そしてこれは京大の下線部和訳で落ちる原因そのもの。→ 実装順 ⑨

## 京大英語から逆算する

2026年度は長文2題（約730語・約580語、下線部和訳2＋内容説明1）＋和文英訳＋自由英作文
（80〜100語）の4題構成、120分。Z会が挙げる必要な力は**基礎力・精読力・表現力**で、
対策には第三者の添削が要るとされる。

大問別に狙われる力:

- **下線部和訳** — 構文把握（SVOC・関係詞・分詞構文の係り受け確定）と、
  `abstract`（抽象的な／要約）`subject`（主題／被験者／〜を受けやすい）のような
  **基本語の意外な意味**の文脈判断
- **内容説明** — 比喩（`The air was a zoo`）と指示語を本文の内容に翻訳し直す具体化
- **和文英訳** — 「腹をくくる」「岐路」「実り」型の直訳不可能な日本語。
  日本語 → やさしい日本語 → 英語の**和文和訳**3ステップ
- **自由英作文** — 主張 → 理由2つ → 総括

この4つのうち、**構文把握と多義語の文脈判断は自動化できる**。比喩の具体化と
和訳の答え合わせはできない。線はそこに引く（→「作らないもの」）。

### 済んだものの実測

| | |
| --- | --- |
| ① 語義 | 70,358行 → 提示 61,624（12.4% 統合）。統合後の訳の衝突 0。比率が出る語 3,796 → 2,557。文脈判別が作れる語 9,220 → 6,126（失った 3,094 語は元から出題不能） |
| ③ 学習画面 | 3帯構成。問題は画面に収まり、答えは下からせり上がって問題を覆う（押し上げない）。評価ボタンは下端固定。せり上がる高さは画面比で決め、問題はその分だけスクロールして逃がせる |
| ⑥ 英文 | 13ジャンルを3つの取得元で。収集は3つの理由で取りこぼしていた（`cmlimit` は走査数の上限／PMC のライセンスURLは `ali:license_ref` のテキスト／本文の `<p>` は `<sec>` の下とは限らない）。いずれも「取得元が空」に見える形で出る |
| ⑦ 畳む | 2つの解析器が同じ範囲で括った部分木だけ。主動詞を含む部分木は候補から除くので骨格は必ず残る |
| ⑧ 速読 | 語彙・構文・速度の3行。98% を割っていればどれだけ速くてもそちらを先に言う（飛ばしただけなので） |
| ⑨ 誤読 | 基本語 1,028 語が候補。**どの意味でこの文に出ていたかは言わない** |
| ④⑤ 形態素 | 分解できた語 2,525（見出しの 13%）、接辞 116。最も生産的なのは -ly 202 / -er 188 / -ing 171 / -ion 155 / in- 50 / un- 47 |

（argument 2 の語は t1 が説明する）ので、1つずらすと全部品に隣の意味のラベルが付く。
`non-<id:not>` `-y#etymology_3` のような注記が形に混ざる。confix はハイフンを書かない。

## UI仕様

### ① 語源の格子（実装順 ⑤）

**語根は「意味」、接辞は「演算子」**として分ける。この分け方なら、README が掲げる
「接頭辞が共通しているだけの家族は作らない」という除外ルールを壊さずに接辞が入る。

```
語根    意味の核        duc = 導く
接頭辞  方向・否定の演算  intro-=内へ  re-=戻す  con-=共に  pro-=前へ
接尾辞  品詞の変換       -tion=名詞   -ive=形容詞   -ize=動詞
```

**分解バー**（1語のページの最上段）:

```
introduction        名  /ˌɪntrəˈdʌkʃən/  B1

┌──────────┬──────────┬────────────┐
│  intro-  │   duc    │   -tion    │
│   内へ    │   導く    │  〜すること  │
└──────────┴──────────┴────────────┘
     内へ導くこと  →  紹介・導入
```

各ブロックはタップできる。

**格子** — 語根を固定して接頭辞で並べる:

```
duc / duct   ラテン語 dūcere「導く」

┌────────┬─────────────┬─────────────┬──────────┐
│ intro- │ introduce   │ 内へ＋導く    │ 紹介する  │
│  re-   │ reduce      │ 後ろへ＋導く  │ 減らす    │
│  con-  │ conduct     │ 共に＋導く    │ 実行する  │
│  pro-  │ produce     │ 前へ＋導く    │ 生産する  │
│  de-   │ deduce      │ 下へ＋導く    │ 推論する  │
│   e-   │ educate     │ 外へ＋導く    │ 教育する  │
└────────┴─────────────┴─────────────┴──────────┘
```

**軸の入れ替えが発明**。左端の `re-` をタップすると縦横が入れ替わる:

```
re-   「後ろへ・再び」

┌────────┬─────────────┬─────────────┬──────────┐
│  duc   │ reduce      │ 後ろへ＋導く  │ 減らす    │
│  ject  │ reject      │ 後ろへ＋投げる │ 拒否する  │
│  port  │ report      │ 後ろへ＋運ぶ  │ 報告する  │
│ spect  │ respect     │ 後ろへ＋見る  │ 尊敬する  │
│  sist  │ resist      │ 後ろへ＋立つ  │ 抵抗する  │
└────────┴─────────────┴─────────────┴──────────┘
```

紙の語源本は「語根ごとのリスト」しか持てない。**紙は1次元だから接辞の軸を持てない。**
同じ `re-` が別の語根でも同じ働きをする、という一番効く気づきが紙では出てこない。
アプリでしかできない見せ方であり、そのまま独自要素になる。

**空きマス** — 未学習の語を薄く出す:

```
│  de-   │ deduce      │ ░░░░░░   │   ← 未学習
│  in-   │ induce      │ ░░░░░░   │   ← 未学習
            あと2語でこの系列が埋まります
```

系列が埋まると未知語を推測できるようになるので、動機と実利が一致する。

### ② 文を畳む（実装順 ⑦）

構文解析は端末でやらない。**パイプライン側で全文を解析して、木ごと積む。**

```
tools/step7_passages.py
  ├ 収集     ジャンル別に本文を取得
  ├ 解析     spaCy で依存構造解析（en_core_web_sm は MIT）
  ├ 照合     Stanza でもう一度解析し、一致した文だけ構文練習に使う
  └ 格納     passages.dbz に本文＋構文木
```

2つのパーサの一致を採るのは品質担保のため。パーサの精度は平易なニュースで95%前後、
**難解な学術散文ほど落ちる**——つまり一番欲しい文で一番外す。一致フィルタなら
「自信がない文は構文練習に使わない（読むだけには使う）」と正直に切れる。

```
Although the evidence that had been gathered over the preceding
decades suggested otherwise, most researchers continued to assume
that the process was essentially random.

                    ［ 畳む ］

Although the evidence ⌄ suggested otherwise, most researchers
continued to assume that ⌄ .

                    ［ 畳む ］

most researchers continued to assume ⌄ .
        S                V              O
```

畳む対象は UD のラベルで機械的に決まる — `acl:relcl`（関係節）/ `advcl`（副詞節）/
`nmod`・`obl`（前置詞句）/ `appos`（同格）/ `ccomp`・`xcomp`（補文）。
全部 subtree なので、**畳む＝部分木を `⌄` に置き換えるだけ**。

京大の下線部和訳の第1段階（構文把握）そのものであり、見た目が完全に新しい。

### ③ 速読モード（実装順 ⑧）

読解に必要な語彙カバー率は **98%**（Hu & Nation 2000）。95%は「最低限の理解」の線で、
98%が「辞書なしで不自由なく読める」線。受験で必要とされる速度はおおむね 150 wpm、
高校生の平均は 75 wpm 前後と言われる（※速読事業者の数字なので目安として扱う）。

ここから出る結論:

> **カバー率が98%を割っている英文で速読訓練をしても、効果はゼロ。**

止まるのは目の動かし方のせいではなく、知らない語で止まっているから。市販の速読教材も
速読アプリも、全部が「訓練の問題」だと仮定して始まる。**語ごとの記憶状態を持っている
このアプリだけが切り分けられる。**

```
読了  742語 / 5分12秒 → 143 wpm

  語彙  99.1%  ✓ 足りている
  構文  3文で係り受けを取り違え         ← 畳んで確認する
  速度  143 wpm  ✓ 入試水準（目安150）

  → あなたの問題は構文です。速読練習ではなく、この3文。
```

**教材を選ばせない。** カバー率は全パッセージについて計算できる（`data/TextAnalysis.kt`
が既にやっている）ので、

- **速読モード** → 98%超のパッセージから出す。訓練が成立する英文しか出てこない
- **語彙モード** → 93〜97%のパッセージから出す。読む練習ではなく不足語を刈る素材

実力が上がると出てくる英文が勝手に上がる。ユーザーは一度もレベルを選ばない。
逃げ道として全パッセージ一覧は残す。

### ④ 誤読リスク（実装順 ⑨）

読み終わった**直後**に出す。読む前に出したらただのヒントだが、読んだ後だと
「自分は読めていなかった」という発見になる。

```
読了  143 wpm ・ カバー率 99.1%

でも、この2語は取り違えているかもしれません
  ▸ subject   あなたは 名「主題」で学習済み
              この文は 27% の「〜を受けやすい」側の可能性
  ▸ abstract  あなたは 形「抽象的な」で学習済み
              この文脈は 名「要約」側の可能性
```

**ぼやけた語ではなく、くっきり見えている語に下線が引かれる。**

実装は3段階に分ける。

- **第1段（WSD不要・確実）** — 「この語には、あなたが学習していない20%以上の意味がある」
  とだけ出す。**どの意味かは言わない。** 嘘をつかない。基本語（CEFR A1–B1 または NGSL）
  かつ2位語義が20%以上かつ訳が別物、で **995語**が該当する
- **第2段（簡易 Lesk）** — 文中の内容語と各語義の英英定義＋例文の語の重なりで判定する
  古典手法。`def_en` 70,358 と例文 66,502 が既に端末内にあるので**追加データ0で動く**。
  実際に使えるかは実測してから決める
- **第3段** — コロケーション 15,091件で補強

### ⑤ 構文確定クイズ（実装順 ⑩）

和訳させて採点はしない（→「作らないもの」）。代わりに**和訳が崩れる原因だけ潰す**。

```
下線部  ...the evidence that had been gathered suggested otherwise...

訳す前に、構文を確定してください

  Q1  この that は？
        ① 関係代名詞（主格）   ② 同格の that   ③ 接続詞
  Q2  suggested の主語はどれ？
        ① evidence  ② that  ③ decades

  ✓ ここを外すと、和訳は必ず落ちます
```

構文木から自動生成できて、模範和訳が要らず、嘘をつかない。京大の減点は大半がここ。

## 同梱する英文（実装順 ⑥）

**貼らせない。** 貼らせた時点で大半の人は使わない。最初から装填する。
13ジャンル × CEFR 5段階 × 各40〜50本 = **約3,000本**、各700〜900語（京大の長文と同尺）。

| ジャンル | 出典 | ライセンス |
| --- | --- | --- |
| 自然科学（生物・地学・気象） | NASA / NOAA / USGS / NSF | パブリックドメイン（米連邦著作物） |
| 医学・脳科学・心理 | PMC OA *Commercial Use* 群、NIH | CC BY / CC0 / PD |
| 技術・AI・情報 | arXiv の CC BY 論文、English Wikipedia | CC BY / CC BY-SA 4.0 |
| 環境・気候 | EPA / NOAA、UNEP、World Bank | PD / CC BY |
| 経済・開発 | World Bank Open Knowledge Repository、FRB | CC BY / PD |
| 歴史・文明論 | English Wikipedia | CC BY-SA 4.0（既に使用中） |
| 哲学・思想 | Project Gutenberg の古典、Wikipedia | PD / CC BY-SA |
| 言語・教育 | PMC OA、Wikipedia | CC BY / CC BY-SA |
| 芸術・文化 | Smithsonian Open Access、Met Open Access | CC0 |
| 社会・メディア・政治 | VOA、Wikinews | PD / CC BY |
| 物語・文学 | Project Gutenberg | PD |
| 随筆・演説 | Gutenberg のエッセイ集、米大統領演説、Wikisource | PD |
| 時事（やさしい） | VOA Learning English（元から3段階の語彙統制） | PD（要クレジット） |

VOA は米連邦機関の著作物なのでテキストはパブリックドメイン（`learningenglish.voanews.com`
へのクレジットが必要。AP/Reuters 由来の写真・動画は対象外なので採らない）。
PMC は Commercial Use 群（CC BY / CC0）だけを NCBI FTP から採る。

Project Gutenberg は当初「19世紀文学は京大の現代論説とズレる」として却下したが、
**ジャンル全網羅なら物語文と随筆は必須**なので採用する。京大の和文英訳は一貫して
「随筆的な人生論」であり、長文にも物語調は出る。

### DB を分ける

```
app/src/main/assets/
  content.dbz     語彙DB（現状 15.3MB）      ← 触らない
  passages.dbz    本文＋構文木（新規）        ← 別ファイル
```

学習記録を語彙DBと分けてあるのと同じ理由。パッセージだけ差し替えるリリースが打てる。
英文は今後いくらでも足せる資産なので、独立させておく。

## 測って見送ったもの: Lesk による語義判定（⑪）

「この文では22%側の意味」まで言う第2段は、簡易 Lesk（文中の内容語と各語義の英英定義の
重なり）で当てられるか検算した結果、**見送り**。

まず辞書の例文で測ると 84.7%、定義だけを署名にすると差3以上で 100% という数字が出た。
これは漏洩で、**辞書の例文は定義を言い換えて書かれる**ので「例文が自分の定義と語を
共有するか」を測っていたにすぎない。転用できない。

語義タグ付きの実文（SemCor、WordNet 3.0 の同梱コーパス）で測り直した。

```
評価項目 294（SemCor の文 × 当アプリが2語義以上を持つ語）
  最頻語義ベースライン                13.6%
  差1以上でのみ発言:  正解率 33.3% / 発言率 13.3%
  重なり0（何も言えない）                86.7%
```

**実文では語義定義と文の内容語がそもそも重ならない。** 8割以上の場面で Lesk は無言で、
発言したときも3回に1回しか当たらない。これで「この文は要約の意味です」と出すのは、
黙っているより悪い。

したがって:

- **誤読リスクは第1段のまま**（意味があることは言い、どの意味かは言わない）
- **語源分解の「推測に使える」印も出さない**。同じ道具に頼る予定だったため

評価項目が 294 件と少ないのは、SemCor の synset と当アプリの見出しの対応で多くが
落ちるため。数字自体は粗いが、向きは動かない。端末内で語義判定をするなら、
Lesk ではなく別の手段が要る。

## 作らないと決めたもの

README と `tools/SOURCES.md` に既にある「入れない」判断（訳のない語は収録しない／
JMdict の逆引きをしない／熟語を1,009項目に留める／音声を同梱しない）に、以下を足す。

| | 理由 |
| --- | --- |
| **和訳の自動採点** | 模範和訳が無い。作れば著作物になり、同梱データの由来が濁る |
| **比喩・指示語の具体化の出題** | `The air was a zoo` が何を指すかは本文依存で、機械的に決まらない |
| **読解の理解度設問** | オフラインで自動生成すると質の悪い問題しか作れない。第1段では作らない。第2段でやるなら既存の CLOZE の仕組みで段落から内容語を抜く方式が現実的だが、それは「理解度」ではなく**読み飛ばし検出**と正直に呼ぶ |
| **語源分解の意味推測を全語に出すこと** | `understand` = under + stand のように現代の意味と繋がらない語がある。分解は全語に出すが、「推測に使える」印は繋がるものだけに付ける。判定は語根の gloss と語義定義の語の重なり（⑪の Lesk と同じ道具） |
| **「いま何%読める」を看板にすること** | 読めば分かる。内訳の一行に格下げする |
| **通信** | 端末内で完結する設計は維持する。したがって LLM による添削は現時点で採らない |

判断の基準は一つ。**答えられない問題・裏付けのない表示は作らない。**
